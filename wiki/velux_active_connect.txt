====== VELUX Active Connect ======

**Status:** Beta / Community-Test   **Version:** 0.5.9   **Minimum LoxBerry:** 4.0.0

VELUX Active Connect verbindet VELUX ACTIVE mit LoxBerry und Loxone. Sensor- und Gerätezustände werden automatisch abgerufen und die gewünschten Werte frei konfigurierbar per UDP an Loxone übertragen. Unterstützte VELUX-Dachfenster können zusätzlich über das Plugin oder direkt aus Loxone gesteuert werden.

===== Funktionen =====

  * Verbindung zu VELUX ACTIVE
  * Automatische Erkennung von Homes und Geräten
  * Temperatur, Luftfeuchtigkeit, CO₂ und Regenstatus
  * Frei wählbare UDP-Werte für Loxone
  * Wahlweise alle Werte oder nur Änderungen senden
  * Konfigurierbares automatisches Abrufintervall
  * Heartbeat zur Überwachung
  * Miniserver-Auswahl aus der LoxBerry-Grundkonfiguration
  * Web- und UDP-Steuerung
  * AUF, ZU, STOP und Positionssteuerung
  * VELUX Gateway-Kopplung für signierte Befehle
  * Kopplungsstatus auf der Startseite
  * Konfigurierbarer UDP-Sende- und Empfangsport
  * Logging und Diagnose
  * Update-sichere Einstellungen und Gateway-Kopplung
  * GitHub AutoUpdate

===== Voraussetzungen =====

  * LoxBerry 4.0.0 oder neuer
  * VELUX ACTIVE Installation und Benutzerkonto
  * Netzwerkverbindung zu den benötigten VELUX-Diensten
  * Für bestimmte Steuerfunktionen ein erreichbares VELUX Gateway
  * Für UDP eine Verbindung zwischen Loxone Miniserver und LoxBerry

===== Installation =====

  - Plugin-ZIP über die LoxBerry Pluginverwaltung installieren.
  - **VELUX Active Connect** öffnen.
  - Unter **Einstellungen** VELUX ACTIVE Zugangsdaten eintragen.
  - Loxone Miniserver auswählen.
  - UDP-Sende- und Empfangsport konfigurieren.
  - Abrufintervall einstellen.
  - Einstellungen speichern und ersten Abruf durchführen.
  - Unter **UDP Messages** die gewünschten Werte auswählen.
  - Bei Bedarf das VELUX Gateway koppeln.

===== Automatischer Abruf =====

Ab Version **0.5.9** verwendet VELUX Active Connect für den regelmäßigen Abruf den bewährten LoxBerry-Scheduler-Aufbau.

<code>
cron/cron.01min
        |
        v
velux_scheduler.py
        |
        v
worker.py
</code>

Der LoxBerry ruft den Scheduler jede Minute auf. Der Scheduler prüft das unter **Einstellungen** konfigurierte Abrufintervall und startet den VELUX-Worker nur, wenn ein neuer Lauf fällig ist.

Ein Lock verhindert parallele Abrufe.

Wichtig: Das Intervall wird vom **Start des letzten erfolgreichen Abrufs** berechnet. Dadurch verlängert die Laufzeit der VELUX-Abfrage das eingestellte Intervall nicht.

Bei einem fehlgeschlagenen Abruf wird der Erfolgszeitpunkt nicht weitergeschoben. Der Scheduler kann beim nächsten Minutenlauf erneut versuchen.

Auf der Statusseite werden angezeigt:

<code>
Letzter Abruf
09.08.2026 19:30:02

Abrufintervall
5 min

Nächster Lauf ab
09.08.2026 19:35:01
</code>

===== Einstellungen =====

==== VELUX ACTIVE ====

E-Mail und Passwort des VELUX ACTIVE Kontos werden unter **Einstellungen** hinterlegt. Das Passwort selbst wird nicht im Plugin-Log ausgegeben.

==== Loxone UDP - Rückmeldungen ====

Dieser Bereich steuert:

<code>
VELUX ACTIVE -> LoxBerry -> Loxone
</code>

Konfiguriert werden Miniserver, UDP-Sendeport, Sendeverhalten und die gewünschten Werte.

==== UDP-Sendeverhalten ====

**Alle Werte senden:** Die ausgewählten Werte werden bei jedem Abruf erneut übertragen.

**Nur geänderte Werte senden:** Ein Wert wird nur übertragen, wenn er sich gegenüber dem zuletzt gesendeten Wert geändert hat.

==== Loxone UDP-Steuerung ====

Dieser Bereich steuert:

<code>
Loxone -> LoxBerry -> VELUX
</code>

Der UDP-Empfangsport wird unter **Einstellungen** konfiguriert.

===== UDP Messages =====

Nach einem erfolgreichen Abruf können die erkannten Werte einzeln für Loxone aktiviert oder deaktiviert werden.

Beispiele:

  * Temperatur
  * Luftfeuchtigkeit
  * CO₂
  * Regenstatus
  * Fensterstatus
  * weitere von VELUX bereitgestellte Werte

Die Auswahl bleibt bei normalen Updates erhalten.

===== VELUX Gateway Kopplung =====

Für bestimmte signierte Steuerbefehle kann eine Kopplung mit dem VELUX Gateway erforderlich sein.

Die Kopplung befindet sich unter **Einstellungen -> VELUX Gateway Kopplung**.

Der LoxBerry muss das Gateway auf TCP-Port ''25050'' erreichen können. Für die Kryptografie wird ''python3-cryptography'' benötigt.

Nach erfolgreicher Kopplung werden Schlüssel und Kopplungsinformationen update-sicher gespeichert.

===== Status =====

Beispiel:

<code>
Status: Verbunden
Gateway Kopplung: Gekoppelt
</code>

Zusätzlich werden letzter Abruf, Abrufintervall und nächster geplanter Lauf angezeigt.

===== Loxone UDP-Steuerung =====

In Loxone Config einen **Virtuellen UDP Ausgang** anlegen.

Adresse:

<code>
/dev/udp/LOXBERRY-IP/PORT
</code>

Beispiel:

<code>
/dev/udp/192.168.1.11/7001
</code>

**Verbindung nach Senden schließen** aktivieren.

Befehlsformat:

<code>
velux.cmd.GERAET.BEFEHL=WERT
</code>

**AUF**

<code>
velux.cmd.dachfenster_bad.open=1
</code>

**ZU**

<code>
velux.cmd.dachfenster_bad.close=1
</code>

**STOP**

<code>
velux.cmd.dachfenster_bad.stop=1
</code>

**Position 50 %**

<code>
velux.cmd.dachfenster_bad.position=50
</code>

Bei digitalen Befehlen den Befehl in **Befehl bei EIN** eintragen und **Befehl bei AUS** leer lassen.

Die Steuerungsseite zeigt die zur eigenen Konfiguration passenden Beispiele an.

===== Logging =====

Das Log zeigt Datenabruf, Scheduler, UDP-Kommunikation und Steuerbefehle.

Scheduler-Beispiel:

<code>
Scheduler: Intervall=5 min, Lauf fällig
Worker gestartet
...
Abruf OK
Scheduler: Lauf erfolgreich, nächster Lauf ab ...
</code>

===== Backup und Updates =====

Bei normalen Updates bleiben insbesondere erhalten:

  * VELUX ACTIVE Zugangsdaten
  * Miniserver- und UDP-Konfiguration
  * Auswahl der UDP Messages
  * Gateway-Kopplung und Schlüssel

===== Fehlerbehebung =====

==== Automatischer Abruf läuft nicht regelmäßig ====

Version **0.5.9 oder neuer** verwenden.

Im Log nach ''Scheduler:'' suchen. Bei einem erfolgreichen Lauf müssen ''Worker gestartet'', ''Abruf OK'' und anschließend ''Scheduler: Lauf erfolgreich'' erscheinen.

==== UDP-Werte kommen nicht in Loxone an ====

  * UDP-Ausgabe prüfen
  * Miniserver und Sendeport prüfen
  * gewünschte UDP Messages aktivieren
  * Firewall prüfen
  * Plugin-Log prüfen

==== Loxone-Steuerung funktioniert nicht ====

  * UDP-Empfangsport prüfen
  * virtuellen UDP-Ausgang prüfen
  * IP-Adresse des LoxBerry prüfen
  * **Verbindung nach Senden schließen** aktivieren
  * Plugin-Log prüfen
