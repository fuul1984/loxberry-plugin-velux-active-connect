\====== VELUX Active Connect ======

**Status:** Beta / Community-Test   **Version:** 0.5.12   **Minimum LoxBerry:** 4.0.0

VELUX Active Connect verbindet VELUX ACTIVE / VELUX App Control mit LoxBerry und Loxone. Geräte- und Raumwerte werden über die VELUX-Cloud gelesen, ausgewählte Werte per UDP an Loxone gesendet und Fenster können über Web oder Loxone gesteuert werden.

\===== Funktionen =====

- VELUX Cloud Login mit Token-Refresh
- Homes, Räume und Geräte automatisch erkennen
- Temperatur, Feuchte, CO₂, Helligkeit, Luftqualität und weitere Werte
- Regensignal, sofern von VELUX gemeldet
- Frei wählbare UDP-Werte für Loxone
- Alle Werte oder nur Änderungen senden
- Heartbeat
- Web- und UDP-Steuerung: AUF, STOP, ZU und Position
- Gateway-Kopplung für signierte Befehle
- VELUX ACTIVE Automatisierung wieder aktivieren
- Plugin auf der Statusseite aktiv/inaktiv schalten
- Einstellungen und Kopplung bleiben bei Updates erhalten
- GitHub AutoUpdate

\===== Loxone Steuerung =====

Virtueller UDP-Ausgang:

\<code ->
/dev/udp/LOXBERRY-IP/7001

Beispiele:

\<code ->
velux.cmd.dachfenster_bad.open=1
velux.cmd.dachfenster_bad.stop=1
velux.cmd.dachfenster_bad.close=1
velux.cmd.dachfenster_bad.position=50

VELUX ACTIVE Automatisierung wieder freigeben:

\<code ->
velux.cmd.velux_active.automation=1

Der Automatisierungsbefehl verwendet das signierte Gateway-Szenario ''home'' und benötigt eine erfolgreiche Gateway-Kopplung.

\===== Gateway-Kopplung =====

Die Gateway-Kopplung wird unter **Einstellungen** durchgeführt. Die Signierschlüssel werden lokal gespeichert und bleiben bei normalen Updates erhalten.

\===== Scheduler =====

Der LoxBerry-Cron läuft jede Minute. Das konfigurierte Abrufintervall entscheidet, wann der nächste Cloud-Abruf ausgeführt wird. Für den aktuellen Testbetrieb werden 3 Minuten empfohlen.

\===== Logging =====

Cloud-Abrufe, UDP-Nachrichten, Steuerbefehle und Fehler werden protokolliert. Zugangsdaten, Tokens und private Signierschlüssel werden nicht im Klartext ausgegeben.

Bei einer Neuinstallation wird das Hauptlog geleert. Bei einem Update bleibt es erhalten.
