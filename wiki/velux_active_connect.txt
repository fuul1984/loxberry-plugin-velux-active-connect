\====== VELUX Active Connect ======

**Status:** Beta / Community-Test   **Version:** 0.5.12   **Minimum LoxBerry:** 4.0.0

VELUX Active Connect verbindet VELUX ACTIVE mit LoxBerry und Loxone. Geräte- und Raumwerte werden automatisch gelesen und ausgewählte Werte per UDP an Loxone übertragen. Unterstützte Dachfenster können per Web oder UDP gesteuert werden.

\===== Funktionen =====

- VELUX ACTIVE Cloud-Anbindung
- Homes, Räume und Geräte automatisch erkennen
- Temperatur, Feuchtigkeit, CO₂, Helligkeit und weitere Werte
- Regenstatus, sofern von VELUX gemeldet
- Frei wählbare UDP-Werte für Loxone
- Alle Werte oder nur Änderungen senden
- Heartbeat
- Steuerung: AUF, STOP, ZU und Position
- Gateway-Kopplung für signierte Positions-/AUF-Befehle
- Plugin auf der Statusseite aktiv/inaktiv schalten
- VELUX ACTIVE Automatisierung wieder aktivieren
- Einstellungen und Kopplung bleiben bei Updates erhalten
- GitHub AutoUpdate

\===== Abrufintervall =====

Für den aktuellen Betrieb werden **3 Minuten** empfohlen.

\===== Loxone Steuerung =====

Virtueller UDP-Ausgang:

\<code ->
/dev/udp/LOXBERRY-IP/7001

Beispiele:

\<code ->
velux.cmd.dachfenster_bad.open=1
velux.cmd.dachfenster_bad.stop=1
velux.cmd.dachfenster_bad.close=1
velux.cmd.dachfenster_bad.position=50

\===== VELUX ACTIVE Automatisierung =====

Nach manueller Fenstersteuerung kann der Fenstermodus auf ''manual'' stehen.

Mit folgendem Befehl wird die VELUX ACTIVE Automatik wieder freigegeben:

\<code ->
velux.cmd.velux_active.automation=1

Intern setzt das Plugin die betroffenen VELUX-Fenster auf:

\<code ->
mode=algo_available

''manual'' bedeutet Automatik aus.

''algo_available'' und ''algo_active'' bedeuten Automatik aktiv.

Der Befehl ist auch als Button auf der Seite **Steuerung** verfügbar.

\===== Gateway-Kopplung =====

Die Gateway-Kopplung wird für signierte AUF-/Positionsbefehle verwendet. Die Kopplungsdaten bleiben bei normalen Updates erhalten.

\===== Plugin Aktiv/Inaktiv =====

Auf der Statusseite kann das Plugin aktiviert oder deaktiviert werden.

Bei **Inaktiv** werden automatische Abrufe und eingehende UDP-Steuerbefehle gestoppt. Einstellungen und Kopplung bleiben erhalten.

\===== Logging =====

Cloud-Abrufe, UDP-Nachrichten, Steuerbefehle und Fehler werden protokolliert.

Bei einer Neuinstallation wird das Hauptlog geleert. Bei einem Update bleibt es erhalten.
